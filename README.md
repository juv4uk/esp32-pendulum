# esp32-pendulum

Вимірювання періоду, Q-фактора (добротності), затухання та виведення
`g` реального фізичного маятника через магнітний кутовий датчик AS5600
на ESP32-S3. Ціль проєкту подвійна: реальний вимірювальний інструмент
(в'яжеться з окремим інтересом до маятникових годинників) і водночас
навчальний проєкт — серйозне занурення в C через щось конкретне, а не
абстрактні вправи.

## Походження — чесно про це

У липні 2026 вже існувала робоча версія цього проєкту (~1500 рядків,
`main.c`/`as5600.c`/`rational.c`/CMakeLists.txt), яку зовнішній аудит
(ChatGPT, 2026-07-25) детально розібрав і запропонував переархітектурити.
**Сам код тієї версії на момент старту цього репо не був доступний** —
він існував лише як файлові вкладення в тому чаті, а не текст, і не
знайшовся на диску. Тому це не відновлення старого коду, а **чистий
рестарт за планом з того аудиту** — архітектура нижче копіює той план
майже дослівно, реалізація вся написана заново, з нуля, крок за кроком.

Якщо оригінальні файли колись знайдуться (інший диск, бекап) —
порівняти зі свіжою версією буде окремо корисно.

## Залізо

- **ESP32-S3-N16R8** (2 ядра Xtensa LX7, 16MB Flash, 8MB Octal PSRAM) —
  ще не підтверджено, що це саме та плата, яка фізично є в наявності;
  перевір перед `idf.py set-target`.
- **AS5600** — магнітний датчик кута, I2C, 12-біт (0..4095 на оберт).

## Правило проєкту: без `float`/`double` у самому конвеєрі

Уся математика — через `Rational32`/`Rational64` (точна раціональна
арифметика, `components/math`). `double` дозволений щонайбільше на
самому виході (друк у консоль) — і то не обов'язково. Це свідомий вибір
з оригінального аудиту, не випадковість: раціональна арифметика на
мікроконтролері без FPU для double — це і продуктивність, і
детермінізм, і привід реально зрозуміти, чому `float` не завжди
правильна відповідь.

## Архітектура

```
components/
    math/       — Rational32/64: mul/add/sub/compare/average, overflow-safe
    drivers/    — as5600.c: I2C-читання кута, медіанний фільтр
    physics/    — конвеєр вимірювання (одна відповідальність на файл):
    tasks/      — тонкі FreeRTOS-обгортки над physics/drivers (не навпаки)
main/
    app_main.c  — стартова точка, під'єднує tasks/
```

Конвеєр (`components/physics/`, кожен файл — один крок):

```
AS5600 (сире 0..4095, wrap)
    -> unwrap.c            неперервний кут, без стрибків на межі 0/4095
    -> (фільтр, лишається у Rational32)
    -> velocity.c          кутова швидкість
    -> period_estimator.c  перехід через нуль -> період
    -> peak_detector.c     пошук амплітудних піків -> для Q
    -> quality_factor.c    Q БЕЗ log()/math.h (оригінальний баг — залежність
                            від double через Q = π / ln(A1/A2))
    -> gravity.c           період + довжина маятника -> g
```

## Реальні баги з оригінального аудиту, яких ця версія свідомо уникає

1. Переповнення `Rational32` при множенні знаменників (потрібні 64-бітні
   проміжні обчислення) — `components/math/include/rational.h`.
2. Залежність від `double`/`log()` у розрахунку Q — `quality_factor.c`.
3. Гонки між тасками при копіюванні спільних масивів без синхронізації —
   `components/tasks/include/tasks.h`.
4. Пропуски в пошуку піків — `peak_detector.c`.
5. Неправильна обробка wrap AS5600 — `unwrap.c`.

Кожен пункт має власний TODO-коментар у відповідному файлі з точним
поясненням, що саме мало зламатись і як це перевірити.

## Стан зараз

Це **тільки скелет** — CMake-структура, заголовки з сигнатурами,
`.c`-файли з TODO замість тіла. Нічого ще не компілювалось і не
прошивалось (ESP-IDF тут, у цьому середовищі, не встановлений — збірку
і перевірку на реальному залізі робиш ти).

## Порядок навчання (пропозиція, не догма)

1. `components/math/rational.c` — сама арифметика, без заліза взагалі.
   Найкраще місце почати: одразу відчуєш, чому переповнення — це не
   абстрактна проблема.
2. `components/drivers/as5600.c` — перший контакт з реальним I2C і
   реальними помилками шини.
3. `components/physics/*.c`, один файл за раз, у порядку конвеєра вище.
   Кожен можна протестувати окремо (синтетичний вхід замість датчика —
   ідея прямо з оригінального аудиту).
4. `components/tasks/*.c` — FreeRTOS в кінці, коли логіка вже перевірена
   без нього.

## Збірка

```bash
idf.py set-target esp32s3
idf.py build
idf.py -p <порт> flash monitor
```
